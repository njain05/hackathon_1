  - **How a day works** (`backend/app/changes.py`):
    - a date's actual timetable = the published week's entries for that weekday, then that date's changes in order;
    - every change is validated by building the day it would produce and running the **independent clash checker** on it;
    - ignored on a single changed day: weekly `hours` totals, and `wrong_teacher` (a substitute isn't the assigned teacher);
    - also checked: leave, and the teacher's daily maximum;
    - a day with no classes (e.g. Saturday) is allowed for makeup classes.
  - **New tables only**: `leaves` and `day_changes` (kind `substitute` / `cancel` / `extra`, a period range, a link to the leave). The live database needs no migration.
  - **API**:
    - public: `GET /colleges/{ref}/day?date` (actual entries, changes and the day's check) and `GET …/changes?from&to` (max 31 days);
    - `POST …/leaves`: anyone may report leave (a teacher from their phone, `by: "teacher"`), but nothing changes for students until the admin acts. The admin key marks it `by: "admin"`;
    - admin: `GET …/cover?date` (leaves, affected classes with lab periods merged, state, ranked substitutes), `POST/DELETE …/changes`, `DELETE …/leaves/{id}` (also removes its cover), `GET …/extra-slots?date&section_id&teacher_id`;
    - **substitute ranking**: only teachers who are free then, not unavailable, under their daily max and not on leave. Order: teaches this subject, then the subject's department, then anyone, with fewest classes that day first;
    - a new substitute or cancel for a class replaces the old one (changing your mind doesn't stack).

## Problems & fixes
- The project folder was moved, so `backend/.venv/bin/uvicorn` and `pip` point at the old path ("bad interpreter"). `.claude/launch.json` now runs `backend/.venv/bin/python -m uvicorn`; use `.venv/bin/python -m pip` too, or recreate the venv.
- `next typegen` is needed after adding a route folder (e.g. `app/c/[code]`), or `PageProps<"/c/[code]">` fails the type check until the dev server regenerates types.
- A production build can't use a symlinked `node_modules` in a scratch copy (Turbopack refuses files outside the root). Use `cp -cR node_modules` (an APFS clone) instead.
- When the browser pane is hidden, timers are throttled, so the "waking up" wait can run much longer than 90 s in tests. The cached /my copy still shows meanwhile.
- Tailwind v4 only outputs `@theme` variables that a utility class uses. The subject colours are read with `var()` from inline styles, so they were dropped. Fixed by moving them to plain `:root` variables.
- Turbopack again kept serving stale CSS after a `globals.css` edit, and a dev-server restart fixed it. **If a CSS change doesn't show up, restart `npm run dev`.**
- The print preview itself wasn't checked here (the browser's print dialog can't be opened from the test tools). The print markup and page breaks were checked in the page instead. Do a real print preview before the demo.
- Tailwind v4 silently dropped classes defined with `@apply` inside `@layer components`. Fixed by using `@utility btn-primary { ... }`.
- The Next dev server (Turbopack) once kept serving stale CSS after `globals.css` changed. A restart fixed it.
- `create-next-app`'s `.gitignore` pattern `.env*` also hid `.env.local.example`. Fixed earlier with `!.env*.example`.
- `npm audit` reports a high-severity `braces` issue in build tooling only (not shipped to the browser). Left for now; check again before deploying.
- The SheetJS `activeTab` workbook view works but is missing from its TypeScript types, so it is cast with a comment.
- Starlette's TestClient warned that `httpx` is deprecated, so the dev dependencies use `httpx2` instead.
- Teacher load imbalance is the only non-zero penalty on the sample. It counts days off as 0 load, so a teacher with 6 periods a week can't be perfectly even. This is expected and not a bug.
- `create-next-app` made its own `.git` inside `frontend/`. Removed it so the repo has a single git root.
- `frontend/.gitignore` ignored `.env*`, which also hid `.env.local.example`. Added `!.env*.example`.
- Python: use Homebrew's `/opt/homebrew/bin/python3.14` (3.14.8). The old python.org 3.14.0 is still earlier in PATH as `python3`, so create venvs with the full path. **Don't move to 3.15 until OR-Tools ships 3.15 support.** `backend/.python-version` = 3.14.8 for Render (if Render lacks it, set `PYTHON_VERSION=3.12`; nothing in the code needs 3.14).
